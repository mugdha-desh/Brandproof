# BrandProof: deploy guide (Supabase database + Render hosting)

You will end with ONE public link (the Render web service) to give judges.

## What goes where

| Value | Where you get it | Where you put it |
|---|---|---|
| `DATABASE_URL` | Supabase > your project > **Connect** > *Session pooler* string | Render > `brandproof-api` > Environment (also your local `.env` if testing locally) |
| `GEMINI_API_KEY` | https://aistudio.google.com > **Get API key** | Render > `brandproof-api` > Environment |
| `BP_GEMINI_MODEL` | fixed: `gemini-3.1-flash-lite` | already in `render.yaml` |
| `BP_SECRET` | auto-generated by Render | nothing to do |\n| `BP_DEMO_PASSWORD` | choose a strong unique password | Render > `brandproof-api` > Environment (required while demo seeding is enabled) |
| `BACKEND_URL` | the URL Render gives `brandproof-api` | Render > `brandproof-web` > Environment |
| `BP_PUBLIC_URL` | the URL Render gives `brandproof-web` (same as the web service) | Render > `brandproof-api` > Environment. Used for the verify link printed on Proof Pack PDFs |
| `BP_CORS_ORIGINS` | the URL Render gives `brandproof-web` | Render > `brandproof-api` > Environment |
| **Public link for judges** | the URL of `brandproof-web` | Report, README, demo video |

## Step 1: Supabase database (5 min)
1. Sign up at https://supabase.com, **New project**. Set a database password and save it.
2. Open the project, click **Connect** (top bar). Choose **Session pooler** and copy the URI. It looks like
   `postgresql://postgres.abcd1234:[YOUR-PASSWORD]@aws-0-xx.pooler.supabase.com:5432/postgres`
3. Edit it into this exact form (add `+psycopg`, put your real password in):
   `postgresql+psycopg://postgres.abcd1234:YOURPASSWORD@aws-0-xx.pooler.supabase.com:5432/postgres`
   If the password has symbols like `@` or `#`, replace them with `%40` and `%23`.
   Use port **5432** (session mode). Do not use port 6543.
4. You do NOT create tables. The app creates them on first start.

## Step 2: GitHub
Create a private repo and push the `brandproof` folder. `.env` is git-ignored: never commit keys.

## Step 3: Render (10 min)
1. https://render.com > **New > Blueprint** > pick your repo. It creates `brandproof-api` and `brandproof-web`.
2. When asked, paste `DATABASE_URL`, `GEMINI_API_KEY`, and a strong unique `BP_DEMO_PASSWORD`. Do not use `demo1234` on a public deployment.
3. After both deploy, copy each service's URL (top of its page). Check they match the two values in
   `render.yaml` (`BACKEND_URL` on the web service, `BP_CORS_ORIGINS` on the API). If not, edit them in
   Render > Environment and the service redeploys.
4. Open the **brandproof-web** URL. Choose a demo email, then enter the `BP_DEMO_PASSWORD` you configured on the API service.

## Step 4: Check it
- `https://<your-api>.onrender.com/api/health` shows OK.
- Sign in, open **AI disclosure**: model should read `gemini / gemini-3.1-flash-lite`.
- Submit the test text from the testing guide. Newest rows in Recent calls should say `ok`.

## Free-tier notes
- Render free services sleep after 15 minutes idle; the first visit takes ~1 minute. **Open the link yourself
  right before judging.**
- Reviews with AI on can take 30 to 90 seconds. The web app allows up to 5 minutes. Don't double-click.
- Uploaded files live in the Supabase database (`BP_STORAGE=db`), so they survive Render restarts.
- Before sharing publicly keep `BP_SEED=1` only if judges need the fictional demo accounts, and use the unique `BP_DEMO_PASSWORD` you configured. Never use real customer data.

## Run locally instead (Docker)
`.env` needs `GEMINI_API_KEY`. Then `docker compose up --build` and open http://localhost:3000.
Local mode starts its own Postgres container. To use Supabase locally, set `DATABASE_URL` in `.env`.

## If something fails
- Render **Logs** tab of `brandproof-api`: look for `Traceback` or `LLM call ... failed`.
- `password authentication failed`: wrong DB password or unencoded symbol.
- `Network is unreachable` / IPv6 error: you used the Direct connection; use the Session pooler string.
- Browser says "Internal Server Error" after a long wait: check API logs; wake the API by opening `/api/health` first.

## Guided tour for judges
On a new browser session the login page starts a spotlight tour. It points at each box and button and waits for you. When a step needs another page (sign in, open an asset, Proof Pack) the tour pauses with no dimming, and carries on by itself once you reach that page, however you got there (demo card, typed email, menu). Judges can end it, jump to a chapter or restart it from the **Guided tour** button (bottom right). Steps live in `frontend/components/Tour.tsx` (the `STEPS` list). Sample files for the upload step are in `frontend/public/samples/`.

## Browser extension (deployed with the site)
The extension is not a server: it is a Chrome/Edge/Brave add-on that talks to your deployed site. The Render deploy already serves it for download at `https://<your-web>.onrender.com/downloads/BrandProof_browser_extension.zip` (also a button on the Help page). Users unzip it, open `chrome://extensions`, switch on Developer mode, choose Load unpacked, and enter the web URL as the server. Nothing extra to configure: it calls `/api/...` on the same URL, and the browser asks once for permission to contact that site. To refresh the download after editing `extension/`, rebuild the zip: `cd extension && zip -r ../frontend/public/downloads/BrandProof_browser_extension.zip .`. A Chrome Web Store listing is optional and separate (one-time developer fee, review time).

## Optional settings added in Round 3
| Variable | Purpose |
|---|---|
| `BP_STALE_SCAN_HOURS` | Scheduled check interval in hours. Default 24, `0` turns it off. |
| `BP_FACT_FEED_URL` | https address of a CSV or JSON fact feed. Leave empty for no feed. |
| `BP_FACT_FEED_TOKEN` | Bearer token sent to the feed, if it needs one. |
| `BP_FEED_ALLOW_HTTP`, `BP_FEED_ALLOW_PRIVATE` | `1` only for local testing. Allow http and private addresses for the feed. |

If you run more than one server instance, run the scheduler on one of them.
